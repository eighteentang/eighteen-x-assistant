# X-Newfish

在 x.com 上做减法的浏览器扩展 —— 把时间线里不想看的东西挡掉，把想看的东西标出来。

> **只做消费端。** 面向创作者与新人的「创作端」能力会另开一个插件，不在本仓库范围内。

> **状态：基础版开发中。** 当前先验证时间线过滤、基础流速徽章和 MAX 权益架构。

## 第一版范围

| # | 功能 | 一句话 |
|---|---|---|
| 1 | 流速徽章 | 每条推文显示每小时浏览量，先做胶囊样式 |
| 2 | 内容过滤 | 屏蔽黄推、特定关键词、非指定语言的推文 |
| 3 | 流速过滤 | MAX 权益：低于指定流速阈值的推文直接隐藏 |
| 4 | 回复辅助 | 暂停开发，后续再启用 |

原则：**先做简单能用的，再拓展。** 不追求一版做全。

## 当前基础版

加载扩展后，在设置页可以配置：

- 总开关
- 关键词过滤
- 基础流速徽章
- 右侧本页流速榜
- 最低流速过滤开关与阈值

流速数据现在从 X 页面已经发出的 GraphQL 响应中提取：按 Tweet ID 缓存浏览量、互动数据和发帖时间，再计算每小时浏览量。DOM 只负责定位帖子和展示，不再从按钮文字猜测数字。没有收到对应网络数据时，徽章显示「流速等待」，不会伪造数值。

右侧「本页流速榜」只统计当前页面已经加载、且已经拿到真实指标的帖子，按流速从高到低排列；点击榜单项目会滚动到对应帖子。

流速徽章分为五档：`🌱 平稳`（低于 100/h）、`↗️ 起量`（100-999/h）、`📈 加速`（1,000-4,999/h）、`🚀 爆发`（5,000-9,999/h）和 `☄️ 出圈`（10,000/h 以上）。徽章使用低饱和的绿、黄、橙、红、深紫渐进色。为避免刚发布的帖子因短时间数据造成流速跳变，计算使用 5 分钟稳定窗口。

点击右侧流速榜中的帖子后，扩展会在当前页面即时定位到对应推文，并短暂高亮目标，不改变 X 当前路由。

## 回复风格与 Grok（暂时关闭）

回复风格和 Grok 入口已经预留，但当前版本暂时不加载、不显示按钮，避免影响流速勋章验证。后续重新启用前，需要重新验证 X 页面结构和 Grok 会话链路。

- 在帖子或回复旁点击「收藏风格」，样本只保存到本机 `chrome.storage.local`
- 插件从样本中统计长度、句子数、问句、感叹号、表情和常见表达特征
- 新样本加入后重新计算个人风格档案，最多保留 100 条样本
- 点击「Grok 回复」后，把当前帖子和本地风格档案交给 X 内置 Grok
- Grok 返回候选后，点击候选即可填入 X 回复框
- 不自动点击发送，不批量回复，不后台扫描时间线

首次使用 Grok 前，需要先打开 `x.com/i/grok`，在当前 X 登录账号中手动发送一条消息。这样页面才会产生当前会话需要的请求签名，插件才能复用浏览器登录态。插件不保存 X 密码，也不把样本发送到自己的服务器。

这套能力参考 `Icy-Cat/x-viral-monitor` 的具体链路：它在页面主世界 Hook X 的 `fetch` / `XMLHttpRequest`，捕获 Grok 请求所需的会话信息；隔离世界只负责显示按钮、候选结果和填回回复框。当前项目新增了 `x-net-hook.js`、`grok-reply.js` 和 `style-profile.js`，但仍需在真实登录的 X 页面验证 X 结构变化后的兼容性。

## MAX 权益

MAX 是统一的高级权益层，不与具体支付渠道绑定。当前版本只定义权益模型，不接入真实支付。

预留权益包括：

- 流速过滤
- 高级筛选
- 回复风格分析
- 候选回复生成

未来可通过账户和授权服务解锁 MAX；支付宝、微信或国际支付平台都只负责更新服务端授权状态，插件本身不保存支付信息。

## 开发与自测

本项目没有构建步骤和运行时依赖。开发者模式加载本目录即可。

```bash
node dev/selftest.js
```

修改代码后，在 `chrome://extensions/` 刷新扩展，再刷新 X 页面。

## 技术前提

要拿到「每小时浏览量」，只能从 X 的 GraphQL 响应里取指标 —— 当前实现已经 hook 页面的 `fetch` / `XMLHttpRequest`，递归解析时间线响应中的 Tweet 结果，并按 Tweet ID 同步到内容脚本。

这不是可选项，砍功能也省不掉：只要涉及推文指标，就得走这条路。详见 Issues 里的「技术前提」。

当前没有网络指标时不使用错误的 DOM 数字作为替代；后续可以再增加明确标注的低精度 DOM 降级。
