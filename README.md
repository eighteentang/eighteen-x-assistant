# X-Newfish

在 x.com 上做减法的浏览器扩展 —— 把时间线里不想看的东西挡掉，把想看的东西标出来。

> **只做消费端。** 面向创作者与新人的「创作端」能力会另开一个插件，不在本仓库范围内。

> **状态：基础版开发中，MIT 开源。** 已实现的功能均可直接使用，无需注册或激活。当前重点验证时间线过滤、流速徽章和本页流速榜。

## 第一版范围

| # | 功能 | 一句话 |
|---|---|---|
| 1 | 流速徽章 | 每条推文显示每小时浏览量，先做胶囊样式 |
| 2 | 内容过滤 | 按关键词和允许语言筛选推文 |
| 3 | 流速过滤 | 低于指定流速阈值的推文直接隐藏 |
| 4 | 账号白名单 | 指定账号不受过滤规则影响 |
| 5 | 过滤恢复 | 显示过滤原因，可临时恢复或将账号加入白名单 |

原则：**先做简单能用的，再拓展。** 不追求一版做全。

## 当前基础版

加载扩展后，在设置页可以配置：

- 总开关
- 关键词过滤
- 账号白名单
- 语言过滤与允许语言列表
- 基础流速徽章
- 右侧本页流速榜
- 最低流速过滤开关与阈值
- 首页、列表、个人主页、详情与回复的独立过滤规则
- 账号黑名单与域名黑名单

点击扩展图标打开 Popup，使用「常用 / 过滤规则 / 榜单」三个标签页。常用开关在首屏，保存与生效反馈固定在底部；榜单的排序、时间范围、条数、收起状态和背景不透明度也可在 Popup 中修改。

流速数据从 X 页面已经发出的 GraphQL 响应中提取，按 Tweet ID 缓存浏览量、互动数据和发帖时间。页面中的本帖互动计数变化时，悬浮详情会同步更新；引用帖和卡片中的计数不参与本帖统计。浏览量或时间缺失时，尝试读取本帖的浏览量入口和时间标记，并在详情中注明页面读数及舍入限制；仍缺少数据时显示「流速等待」。

右侧「本页排行榜」只统计当前页面已加载、且未被过滤的帖子，不代表全站热门榜。支持按平均流速、浏览量、点赞数或收藏数降序排列；缺少所选指标的帖子不参与排名，同一帖子只显示一次。

榜单可选择全部时间、最近 1 小时、24 小时或 7 天内发布的帖子，以及 Top 10 / 20 / 50；时间筛选不包含发布时间未知的帖子。每行显示作者、发帖时间和正文摘要，点击可定位到帖子，「原帖」可在新标签页打开。排序、时间范围、显示条数和收起状态保存在本机；设置页可独立关闭榜单，关闭流速徽章不会关闭榜单。窄于 1180px 的窗口继续隐藏浮动榜单。

流速徽章分为五档：`🌱 平稳`（低于 100/h）、`↗️ 起量`（100-999/h）、`📈 加速`（1,000-4,999/h）、`🚀 爆发`（5,000-9,999/h）和 `☄️ 出圈`（10,000/h 以上）。徽章使用低饱和的绿、黄、橙、红、深紫渐进色。为避免刚发布的帖子因短时间数据造成流速跳变，计算使用 5 分钟稳定窗口。

点击右侧流速榜中的帖子后，扩展会在当前页面即时定位到对应推文，并短暂高亮目标，不改变 X 当前路由。

回复弹窗中，徽章只放在具有帖子链接的原帖内部，不给草稿输入区插入徽章；每条帖子最多保留一枚徽章，并清理遗留在帖子外部的旧徽章。

## 可恢复的过滤

被过滤的帖子会显示原因，例如命中关键词、非允许语言或低于流速阈值。点击「显示这条」可临时恢复，再次点击「重新隐藏」可收起；修改过滤规则后重新评估。

账号白名单优先于所有过滤规则。可以在设置页填写 `@用户名`，也可以在过滤提示中点击「始终保留 @用户名」。白名单只保存在本机浏览器。

语言过滤默认关闭，开启后按允许语言列表筛选，支持 `zh`、`en`、`ja`、`ko` 等代码。优先使用 X 返回的语言信息，再使用帖子正文的语言标记；无法确认语言时保留帖子。白名单账号始终保留。

在「过滤规则 → 作用页面」选择全局默认、首页、列表、个人主页或详情与回复。各场景初始继承已有全局设置；关闭「使用全局规则」后，可单独设置关键词、语言、流速阈值、账号及域名黑名单，也可关闭该场景的过滤以保留阅读上下文。重新打开「使用全局规则」会移除该场景的独立配置。搜索等其他页面使用全局规则，回复弹窗使用详情规则。X 在不刷新页面的情况下切换路由时也会重新评估。

账号黑名单按 `@用户名` 匹配，域名黑名单匹配域名及其子域名（`example.com` 匹配 `shop.example.com`，不匹配 `fakeexample.com`）。优先读取本帖网络数据中的已展开链接，也读取正文链接；不额外访问短链、不猜测短链目的地。全局账号白名单优先于所有场景的过滤规则，包括黑名单。

成人引流识别尚未实现。回复生成和个人风格分析已移出本项目。

## 使用方式

所有已实现功能可直接使用。设置和指标缓存在本机浏览器中处理，无需创建产品账号或输入激活码。流速过滤通过设置页的开关和阈值控制。

## 开发与自测

本项目没有构建步骤和运行时依赖。开发者模式加载本目录即可。

```bash
node dev/selftest.js
```

浏览器回归检查（使用模拟帖子、网络数据和存储，不连接 X 账号）：

```bash
node dev/browser-check.js
```

打开 `http://127.0.0.1:18763/` 查看场景结果，`/options` 检查 Popup；`/options?check=1` 额外显示 CSS 规则解析及初始布局检查。检查覆盖总开关恢复、首屏指标交接、动态加载与节点复用、关键词/账号/域名/语言/流速过滤、白名单优先级、分场景规则与无刷新路由切换、过滤恢复、旧版设置兼容、榜单排序/时间/条数/收起/去重、回复弹窗内徽章边界及游离徽章清理。`/?preview=reply` 可保留模拟回复框检查布局。此检查不能替代真实登录 X 后的兼容性验收。

修改代码后，在 `chrome://extensions/` 重新加载扩展，再刷新 X 页面（仅刷新 X 不会更新已注册的脚本列表）。设置开关立即保存，输入框编辑结束后保存；设置页会向已打开的 X 页面确认应用结果，报告已检测、已过滤及有数据的帖子数量，页面未响应时显示重新加载提示。

## 技术前提

优先从 X 的 GraphQL 响应取精确指标：观察页面的 `fetch` / `XMLHttpRequest`，递归解析时间线响应中的 Tweet 结果，并按 Tweet ID 同步到内容脚本。

当前实现不额外请求 X 接口。网络数据和页面标记的结构都可能随 X 更新而变化，需要持续做兼容性验证。

页面降级只读取与本帖 Tweet ID 匹配的浏览量入口、本帖时间和互动按钮，不扫描整张帖子中的任意数字。流速是发布以来的平均浏览量，不代表最近一小时的增量；发布不足 5 分钟按 5 分钟计算。
